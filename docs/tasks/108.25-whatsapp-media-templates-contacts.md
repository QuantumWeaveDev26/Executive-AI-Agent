### Original design notes

The 1083 schema fixes the dispatch draft keys to text-only (`bodyText`, …) and the binding to 1–5 recipients with no audited update path. One reviewed additive migration would:

1. Allow optional draft keys `template` (`name`, `language`, bounded `bodyParams[]`/`headerParams[]`) and `media` (`kind`, uploaded `mediaId`, `mimeType`, `sha256`, optional `caption`/`filename`), with CHECKs that exactly one of `bodyText` / `template` / `media` is present; trigger keeps approval-params equality, revision, sender, opt-in and reply-binding checks. Template drafts are exempt from the 24 h window (that is their purpose); text/media stay inside it.
2. Add audited action `whatsapp.durable.contacts_updated` (binding revision +1, recipients schema unchanged, opt-in required), allowing the owner to add/rename/remove contacts; consider raising the 5-recipient cap via a separate `whatsapp_n8n_contacts` table if more contacts are needed.
3. Extend the audit-proof action list accordingly. No backfill, no change to existing rows, RLS, grants.

Then code: contracts/draft union, durable reserve/claim for template and media drafts, outbound media upload adapter, n8n outbound workflow branch for `template` and media message types (workflow edit approval), Chat "send this PDF to Ram".

Process (as in 108.21): write SQL + PostgreSQL runtime tests → owner-approved **isolated disposable database** run → owner-approved pilot application with backup → deploy code.
