# Step 108.22 — Secure incoming image retrieval and preview

Let the signed-in owner open a preview of a saved incoming WhatsApp **image** on request. Builds on 108.21 metadata. No sending, no file storage, no documents/audio, no migration.

## Design

- **Browser names a saved message, never a file.** `POST /api/v1/connectors/whatsapp/n8n/durable/:connectionId/media/:messageId/preview` (CSRF-protected POST so a cross-site `<img>` cannot trigger downloads). Body must be empty `{}`; no query.
- **Ownership first.** `DurableWhatsAppService.mediaReference` resolves the stored media ID inside the existing owner-scoped transaction (`run()`: session, binding owner, RLS, `assertAuthorized`). Foreign tenant/owner, viewer, relay scope, unknown message, text or non-image → 403 before any provider I/O or audit.
- **Policy.** New registry action `whatsapp.media.preview` (read, low risk, member+, audit required) evaluated by `PolicyGateway`.
- **Provider adapter** (`createMetaWhatsAppMediaProvider`): `GET https://graph.facebook.com/v21.0/{numericMediaId}` then `GET` the returned URL. Only `https://lookaside.fbsbx.com` (no IP literals, ports, credentials, other schemes/hosts); `redirect: 'error'` on both calls; 16 KB metadata cap; 5 MB file cap enforced on `file_size`, `content-length` and while streaming; timeout 15 s. Token comes only from a server-side provider function; absent → `not_configured` with no network call.
- **Verification** (all must pass): JPEG/PNG magic bytes only (SVG, GIF, WebP, HTML refused); matches saved MIME and provider MIME; SHA-256 equals the fingerprint saved from the webhook (hex or base64) and the provider's, when given.
- **Audit, fail closed.** `whatsapp.media.previewed` / `whatsapp.media.preview_refused` in the existing `audit_events` table (target type `whatsapp_media`; session re-resolved). No URLs, media IDs, tokens or bytes in audit. If the audit write fails, no bytes are returned.
- **Inert response.** `Content-Type` from detected type, `nosniff`, `CSP default-src 'none'; sandbox`, `CORP same-origin`, `no-store`, `no-referrer`. Not persisted or cached; `downloadStatus` stays `not_downloaded`.
- **Rate limit.** 20 previews / 10 min per owner (in memory).
- **Truthful errors.** 503 `WHATSAPP_MEDIA_NOT_CONFIGURED`, 429 `WHATSAPP_MEDIA_RATE_LIMITED`, 502 `WHATSAPP_MEDIA_UNVERIFIED`, 403 denied.
- **Web.** "Load image preview" button on saved JPEG/PNG cards only; never loads automatically. Client re-checks type, size and magic bytes, shows a revocable `blob:` URL (`img-src` adds `blob:`), and explains failures in plain words.

## Not covered (honest limits)

- No antivirus scanning or re-encoding; risk is limited by raster-only formats, magic-byte + fingerprint checks and inert serving. Documents/audio stay metadata-only.
- `app.ts` accepts `whatsappMedia` but the pilot does **not** wire a Meta token yet → previews report `not_configured` there. Wiring a server-side token (secret file) and any real Meta download test need owner setup and explicit approval.
- Rate limit is per process and resets on restart.
