# Step 108.23 — WhatsApp Web-style experience, contacts and Chat read commands

Replace the admin-style stored inbox with a two-panel messaging app on the **real** durable records. No mock data, no migration, sending stays disabled.

## Implemented (local)

- **Layout** (`apps/web/src/StoredWhatsAppInbox.tsx`, `styles.css` `.wa-*`): chat list (search, initials avatars, contact name + masked number, last preview with outgoing ticks, list time, per-device "new" badge, recency sort, selection highlight, loading/empty/error) and conversation pane (header with eligibility, oldest-first bubbles, Today/Yesterday/date separators, times, ticks, "New messages" divider, auto-scroll to latest, "Load earlier messages", saved delivery events). Below 760 px: list screen ↔ chat screen with back button. Thaara blue branding; no WhatsApp artwork.
- **Ticks are evidence-only**: sent ✓, delivered ✓✓, read ✓✓ (blue) only from saved statuses; `reserved` = clock "Prepared, not sent"; `unverified` = "Outcome unknown"; failed = red.
- **Composer**: multiline, Enter prepares, Shift+Enter newline (IME-safe), emoji picker, optional "reply to their latest message" context, approval card showing contact + exact text, "Edit or discard", progress/error banners. Attachment button present but disabled with an honest label.
- **Contacts**: `GET /api/v1/connectors/whatsapp/n8n/durable/:id/contacts` (owner-scoped `run()`, no-store, `N8nWhatsAppContactsSchema`): authorized recipients only, masked numbers, `eligible | window_closed | not_opted_in` from opt-in and Meta's 24 h window. New-chat picker; composer blocked with a plain reason when not eligible. Browser rejects unmasked numbers, duplicates, extra fields.
- **Refresh**: quiet 30 s refresh while visible (skipped during loading/reply preparation); chat list kept while a chat is open.
- **Chat read commands** (`chat-whatsapp-read.ts`): latest messages, "unread" (= last-24 h inbound; server read-state not tracked, said explicitly), open/show/summarize a contact's chat (ambiguous names → asks; unknown → refuses; no model summary invented). English, Kanglish, Kannada patterns. Owner scope + policy via existing `connections`/`inbox`. Replies keep the existing approval flow.
