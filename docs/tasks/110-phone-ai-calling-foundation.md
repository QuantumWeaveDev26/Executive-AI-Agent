## Design and bounded implementation plan

Use the existing Fastify/authentication/CSRF, TypeBox contracts, PolicyGateway, approval repository and audit ledger. Preserve the Step 95–97 mock history/briefing contracts. Add a separate `/api/v1/connectors/phone/ai` foundation with live calling unconditionally disabled. No paid provider, network dispatch, recording, production transcript ingestion, schema migration or service change.

1. Add shared call-draft/status/history/report schemas and an explicit high-risk policy action. Contact directory is server-injected and receives authenticated owner/workspace scope. Refuse ambiguous/unconsented/changed contacts; never select an arbitrary match or accept browser-supplied raw dial targets.
2. Persist call approval drafts in the existing approval table, with exact recipient revision/binding hash, purpose, language, AI disclosure, duration, idempotency key and expiry. Scope/member/session checks and audit occur transactionally. No invented consent from user approval.
3. Add a test-only simulated lifecycle, bounded conversation turns, interruption fencing, failure states and evidence-quoted reports. Simulation is explicitly non-durable and never proves a real call. Reports contain only final recipient utterances; incomplete/failed calls cannot imply attendance or agreement. A future speech/Agents SDK engine proposes dialogue only; cannot authorize actions.
4. Prepare a Plivo codec/disabled adapter with one-recipient request validation and fixed endpoint. No actual network dispatch or public callback route. Future provider callback admission must use official SDK V3 signature validation, pinned URL, nonce replay control, call binding and durable event correlation; do not hand-roll an unverified public webhook.
5. Add explicit English/Kanglish/Kannada intent parsing, a Chat preparation path and a Phone screen panel. Production defaults to setup required, with no synthetic contacts/history. Spoken reporting is an explicit browser-user action using the same evidence report; no background microphone or auto-play.
6. Focused domain/HTTP/UI/security tests, contracts/policy/API builds and web build; existing phone/Gmail/Calendar/WhatsApp regressions at the milestone. Existing approved in-memory migration fixtures only.
